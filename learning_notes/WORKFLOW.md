# 协作、提问与归档流程

[返回总目录](README.md)

## 一、学习资料放在哪里

Hello-Agents 的问题以本仓库 `learning_notes/` 为主要归档位置；原教程 `docs/`、`code/`、扩展篇和根 README 不因记笔记而被覆盖。
主章节使用 `chapter01`—`chapter16`；扩展资料放 `extra/`；可复用的基础知识放 `foundations/`，章内保留关联。
无法确定归属时先记到 `pending/`，标记“待定位”，不要强行猜章节或因此中断问题讲解。

## 二、学习者怎样提问

直接发送代码、错误或项目问题即可。能提供时附上章节/小节、文件路径、想实现的功能、实际输出、运行命令和环境。
不要求一次填完表格；已有的信息不重复询问。不要发送真实密钥，完整报错也要先删去身份信息和凭据。

## 三、每轮回答与写入

1. 读取仓库最新状态，以及对应章节已有 notes、questions 和实践记录，避免覆盖用户新改动。
2. 根据路径、函数名和教材内容定位原文小节；记录本轮读取的提交版本。
3. 先解释程序目的和执行顺序，再讲关键语法；明确“教材原写法”“修订建议”“版本差异”。
4. 在本章 `questions.md` 追加问题记录；通用知识整理到 `notes.md`；有实际代码才增加 `practice/001_topic/`。
5. 给一个小练习；能运行的最小示例实际验证，不能验证的明确写出原因和范围。
6. 检查脱敏、引用、相对链接和差异，再提交到本 fork；回读提交结果，返回提交号、变化路径与下一步。

以上是每次实际对话中执行的流程，不是后台监听、定时同步或自动监控聊天。只有写入成功并回读核实，才称“已上传”；失败则说明原因和保留可复制内容。

## 四、编号和文件规则

主章节问题：`CH04-Q001`；准备问题：`PREP-Q001`；扩展问题：`EX07-Q001`；待归档问题：`PENDING-Q001`。
一个编号只表示一个真实问题，不复用。跨章问题指定主章节，其余位置放交叉引用，不复制多份互相矛盾的答案。
短问题直接记录在 questions 中；长案例放 practice 子目录，问题表链接过去。
文件使用简短的小写英文与下划线，中文放标题和正文。保留原代码并注明脱敏/格式整理；修订版不悄悄替换原件。

## 五、内容必须包含什么

问题原意；教材小节和源码路径；必要的环境与版本；直观解释；关键行及数据流；常见错误；修改原因和行为变化；运行命令；验证结果；资料来源；待确认项；一个学习者练习。
知识来源优先教程原文和对应项目/语言的官方文档。动态版本和接口必须重新核对，不把旧教程直接当成当前接口保证。

## 六、状态不是一个“完成”勾

知识：待学习 → 已讲解 → 能独立复述 → 能独立改动并验证。
问题：待分析 → 已解释待验证 → 已验证 → 已复盘；受阻时写具体阻塞。
代码：未运行 / 静态检查 / 离线测试 / 真实服务测试，注明系统和依赖。
资料已创建、助手检查通过、学习者已掌握是三件不同的事。更新 [进度表](progress.md) 时必须有证据。

## 七、写入安全与变更边界

本仓库公开；不上传真实 `.env`、API key、Cookie、数据库、私人聊天全文、原始日志和未脱敏截图。
`.gitignore` 只是防误提交，不会清除已经提交的秘密；泄露后应立即在服务端撤销/轮换，再处理仓库历史。
不自动付费调用，不执行模型生成代码，不修改仓库可见性、权限、Actions 或 Issues 设置。
当前笔记可按学习者授权直接提交 main；改教材代码或大型实验时先用独立分支，不向上游仓库擅自提 PR。
禁止强制推送覆盖用户提交。上游同步见 [Git 指南](00_preparation/git_and_sync.md)。

忽略规则依据：[Git 官方文档](https://git-scm.com/docs/gitignore)。
