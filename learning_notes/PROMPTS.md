# 学习提示词：开场、提问、收尾

[个人入口](../LEARNING.md) · [当前交接](HANDOFF.md) · [协作流程](WORKFLOW.md)

不需要每次写长提示词。固定规则放在仓库，当前状态放在 HANDOFF.md，每次只补本次问题。
本页模板是可复制的任务说明，不保证任何新聊天天然具备仓库读取或写入权限。

## A. 新开聊天：复制一次

```text
@GitHub
我要继续学习 Hello-Agents。我是 Python 和计算机初学者，请用中文带我在代码实践中学习。
仓库：https://github.com/ganeswarrav259/hello-agents

请先实际读取最新 main 分支中的：
learning_notes/HANDOFF.md
learning_notes/AGENTS.md
learning_notes/WORKFLOW.md
learning_notes/progress.md
随后按本次问题读取对应章节的 notes.md、questions.md 和实际源码，不要仅凭旧聊天印象回答。

先用 3—5 句话确认已记录的进度、待验证项和下一步，不要重新初始化仓库。
教学先讲程序目的、输入输出和执行顺序，再拆关键语法，每轮重点讲 1—3 个知识点，并给一个小练习。
我授权把本次与学习有关的脱敏笔记归档到该仓库 learning_notes/，提交到 main；不修改原教材或仓库设置，不强制推送。若我本次说先不上传，则暂不写入。
更新相关问题、知识笔记、进度和交接摘要，成功提交并回读后告诉我提交号、改动路径及验证范围。
不能读取或写入时请明确说明，不要声称已完成；能依据我提供的内容讲解时先继续讲解。

我今天要学 / 问的是：……
```

只需替换最后一行。要换的是聊天时，不用另建 GitHub 仓库；真正改用另一个仓库时，需同时说明新地址、笔记位置和哪些资料允许迁移。

## B. 同一聊天的日常提问：最短版本

```text
继续按仓库的学习约定。
第 4 章 4.1.3，我不懂 self.model = model：左右两边有什么区别？
请用最小例子解释，给我一个小练习，并记录到对应章节。
```

不清楚章节时写“请帮我定位章节”。不清楚任何环境字段时写“不知道”，不用先填完表格才能提问。
通用公式：位置或代码 + 卡点 + 希望达到的目标 + 本轮是否上传。
“逐行解释”“先给提示，不给完整答案”“只讲这一段”“先解释，不上传”都可以直接作为本轮要求。

## C. 带代码学习：保留换行和缩进

````text
继续按仓库学习约定。
章节 / 小节：第 __ 章 __（不知道就请帮我定位）
文件或源码链接：……
这段代码想做什么：……
我目前理解的是：……
我不懂的是：……

```python
# 在这里粘贴完整的相关函数，保留换行和缩进。
```

请先讲整体执行顺序，再拆我不懂的关键行。
区分 Python 语法、第三方库接口和作者自定义命名。
不要只给改好的代码；说明修改原因，并给我一个能自己动手的任务。
将讲解和问题记录到对应章节；原件与修订版分开。
````

代码很多时提供仓库路径和函数名即可，不必把整个项目粘进聊天。不要把终端日志或 >>> 提示符混进源代码。

## D. 遇到报错：材料比提示词长短重要

````text
第 __ 章，我运行代码时遇到问题，请先定位原因，不要直接重写整个项目。
文件路径：……
运行命令：……
执行命令时所在文件夹：……
系统 / Python / 关键依赖版本：……（仓库已有且未改变的不用重填）
我期待的结果：……
实际发生的情况：……
我已经尝试过：……

```text
在这里粘贴从 Traceback 开始到最后一行的报错，先删除密钥和个人信息。
```

请说明哪个结论有证据，哪个只是推测；给最小修改和验证方法。
归档错误现象、原因、修复与验证状态；我尚未验证的内容请不要标记通过。
````

## E. 读项目架构 / 准备做小项目

```text
我要学习第 __ 章的这个项目：路径或链接……
目标：……；当前看不懂的地方：……
请先读取实际文件树、README 和入口代码，解释入口在哪里、主要模块各管什么、一次输入如何到达输出。
遇到 Python 基础请单独拆解，不要默认我已经懂。
先找一个可离线验证的最小任务，不急着重构，不替我写完整大项目。
将架构讲解和实践计划归到对应章节；需要运行外部服务或产生费用时先说明。
```

## F. 交作业 / 检查是否真正理解

```text
我来提交 CH04-Q001 的练习：下面是代码、运行命令和输出。
请先检查正确性与边界输入，再根据我的代码问一个检验理解的问题。
不要只因为我贴出了正确输出就标记整章掌握。
将作答、反馈和确实验证的结果补充到原问题编号，更新进度。
```

## G. 准备结束或换聊天：复制这一段

```text
我要结束本次学习并在新聊天继续。
请先读取仓库最新状态，将本轮确实讨论过的问题和结论归档，更新 learning_notes/HANDOFF.md、progress.md 和 CHANGELOG.md。
交接摘要请写清：学到哪、已讲解什么、我实际验证了什么、未解决问题、相关文件、一个最小下一步。
不知道的环境和结果写“待确认”；没有提交的本地改动不要假装已入库。
保留已有记录，不复制私人聊天全文，不修改原教材。
实际提交并回读后告诉我提交号，同时给一段能直接粘贴到新聊天的接续提示词。
若写入失败，请在回答中完整给出待保存摘要，并说明失败的步骤。
```

## H. 在 ChatGPT 项目中复用的固定说明（可选）

ChatGPT 项目支持项目指令、文件和项目内聊天上下文；实际记忆行为取决于设置。为便于核对，本学习方案仍以仓库中的最新文件为进度依据，而不是要求模型保证记住所有历史。
在项目设置的指令中可放下面这段，不要把每天变化的学习进度写死在固定指令里。

```text
我是一名编程初学者，使用中文学习 Hello-Agents、Python 语法和项目架构。
学习仓库是 ganeswarrav259/hello-agents。新聊天先读取 learning_notes/HANDOFF.md、AGENTS.md、WORKFLOW.md、progress.md 和相关章节材料；读取失败要说明。
先讲程序目的和执行顺序，再拆关键语法，每轮聚焦 1—3 个知识点，用小练习验证。
本项目中与课程有关的实质性问答按章节记录。仓库写入以当前授权和工具能力为准；上传前脱敏，上传后核实，不声称后台自动同步。
不要修改原教程，不用“笔记已生成”代替“我已学会”。我当次提出的学习重点和暂不上传要求应被保留。
```

ChatGPT 项目中的文件与 GitHub 仓库文件在本流程中分别核对，不假定二者已双向同步。新聊天读取失败时，可以上传或粘贴最新 HANDOFF.md 和相关章节材料，并标明来自哪次提交。
官方依据：[Projects in ChatGPT](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)，核对日期 2026-09-11。本页其余模板为本学习仓库的协作设计，不是 OpenAI 官方模板。
